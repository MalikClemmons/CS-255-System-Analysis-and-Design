# CS-255-System-Analysis-and-Design
## DriverPass Project

DriverPass was the client for this project. The company wanted a web-based system that would help customers prepare for their driving examinations through online classes, practice tests, and behind-the-wheel training. The proposed system allows customers to create accounts, select training packages, monitor their progress, and schedule driving lessons. It also supports DriverPass employees by allowing them to manage customer accounts, appointments, instructors, vehicles, training records, reports, and system access.

## What I Did Well

One part of this project that I did particularly well was translating the client interview into detailed functional and nonfunctional requirements. I identified the responsibilities of customers, instructors, the secretary, the owner, and the IT administrator. I also considered requirements involving performance, browser compatibility, security, accessibility, data accuracy, backups, and future growth. Maintaining consistent requirements across the business requirements document and UML diagrams helped create a design that developers could understand and implement.

## Area for Improvement

If I revised one part of my work, I would simplify the more complex UML diagrams. The use case and class diagrams contain many relationships because the DriverPass system supports several users and business processes. I would improve them by reorganizing related elements, reducing crossing lines, and dividing large diagrams into smaller supporting views where appropriate. This would make the system easier for both technical and nontechnical audiences to understand without removing important information.

## Interpreting User Needs

I interpreted the users' needs by identifying what each person needed to accomplish and then connecting those goals to system functions. For example, customers needed a convenient way to schedule lessons, while DriverPass needed to prevent conflicts involving customers, instructors, vehicles, dates, and times. I incorporated both needs by designing a scheduling process that checks all required resources before confirming an appointment. I also designed different access levels so users can view or modify only the information needed for their responsibilities.

Considering users' needs is important because a technically functional system can still fail if it is confusing, inefficient, inaccessible, or inconsistent with the organization's actual processes.

## Software Design Approach

My approach to software design begins with understanding the problem before selecting a technical solution. I identify the users, their goals, business rules, information requirements, limitations, and possible exceptions. I then use models such as use case, activity, sequence, and class diagrams to examine the system from different perspectives.

In future projects, I will continue using interviews, requirement categorization, process modeling, object modeling, traceability, and iterative review. I will also seek user feedback throughout the design process so that assumptions and usability problems can be identified before development becomes costly.
